# Appendix A — AI Verification Log

This log documents the significant uses of AI assistance during implementation of the Robot Management System, in accordance with the CMP9134 AI Usage Policy. AI was used as a "Junior Assistant" — every suggestion was reviewed against the live Virtual Robot API, the project's Acceptance Criteria, and the OWASP Top 10 before being accepted, modified, or rejected.

---

| Task Category | AI Tool Used | Prompt Summary | Verification & Modification |
|---|---|---|---|
| Implement coordinate validation (`server/validation.js`) | Claude Sonnet 4.6 (Claude Code CLI) | "Write a helper that validates the target (x, y) for the Virtual Robot move endpoint." | AI returned a function accepting any `number` for x and y. **Modified:** the live API only accepts **integers** on the 0–20 grid, so I added `Number.isInteger(x)` and `Number.isInteger(y)` checks — the AI version would have let `3.5` through and produced a 422 from the robot. **Added (AI missed):** explicit `Number.isNaN` guard, `typeof === "number"` guard so string `"5"` is rejected before reaching the API, and lower-bound check for negatives. Constants `GRID_MIN`/`GRID_MAX` extracted so the React client and unit tests reuse the same source of truth. |
| Implement robot HTTP client with retry (`server/robotClient.js`) | Claude Sonnet 4.6 (Claude Code CLI) | "Write a Node.js client that wraps the Virtual Robot API (`/api/status`, `/api/move`, `/api/reset`, `/api/map`) and emits connection-state events." | AI returned plain `axios` calls with a simple `for` retry loop. **Modified:** the AI retried on **every** error including 4xx. This would spam the robot with the same invalid coordinates — I changed `_withRetry` to skip 4xx (except 429) and re-throw immediately, so validation failures surface to the user instantly while 5xx/network errors still back off. **Added (AI missed):** exponential backoff with a cap (`Math.min(cap, base * 2 ** attempt)`) so we don't grow unbounded, Singleton enforcement (constructor throws if `_instance` already exists), and `_resetForTests` static method so Jest can install fakes between tests. Verified by running the integration suite with the robot deliberately stopped — saw `reconnecting` → `disconnected` transitions emit correctly. |
| Implement telemetry hook with WS + polling fallback (`client/src/hooks/useTelemetry.ts`) | Claude Sonnet 4.6 (Claude Code CLI) | "Write a React hook that subscribes to `/ws/telemetry` and falls back to `/api/status` polling when the socket drops." | AI returned a `new WebSocket()` inside `useEffect` with no cleanup and no fallback. **Modified:** every handler (`onopen`/`onmessage`/`onerror`/`onclose`) is now nulled out in the cleanup function before `ws.close()` — without this, React 18's StrictMode double-invoke triggered duplicate `setState` calls after unmount and crashed the test suite. **Added (AI missed):** (1) polling fallback (`startPolling`) that kicks in on `ws.onclose` so the UI keeps updating while the socket reconnects; (2) staleness detection — if `lastRxRef` is older than `2 × POLL_INTERVAL_MS` the hook returns `stale: true` so the dashboard can show "Signal Lost" per US-07 AC; (3) `cancelledRef` so async ticks fired after unmount become no-ops. All long-lived state moved into `useRef` to avoid stale-closure bugs the AI version had. |
| Implement JWT + RBAC middleware (`server/auth.js`) | Claude Sonnet 4.6 (Claude Code CLI) | "Add `authenticate` and `requireOperator` Express middleware using JWT — viewers can read, only operators can command the robot." | AI returned `jwt.verify(token, secret)` and trusted the entire payload. **Modified:** payload trust narrowed to **`{ sub, role }`** only — the middleware now rejects tokens missing either claim (`if (!payload?.sub || !payload?.role) return null`). Without this, a token signed with `{ admin: true }` would have authenticated as a phantom user with `req.user.role === undefined`, which `canCommandRobot` would correctly deny — but `req.user.username` would be `undefined` and end up in the audit log. **Added (AI missed):** (1) `extractToken` reads from both the `Authorization: Bearer` header **and** the `?token=` query string, because the WebSocket upgrade in `wsRelay.js` cannot set custom headers; (2) `DISABLE_STATIC_TOKENS=1` env flag so the dev-only `viewer-token` / `operator-token` shortcuts cannot accidentally ship to production. Verified by writing `test_auth.test.js` cases that forge a payload with no `role` claim — confirmed rejected with 401. |
| Fix mongo-memory-server runtime in Docker (`server/Dockerfile`) | Claude Sonnet 4.6 (Claude Code CLI) | "Why does my Jest integration suite pass locally but fail in `docker compose up` with `MongoNetworkError`?" | AI initially suggested mounting a real MongoDB volume — wrong root cause. **Rejected** that suggestion: the test suite uses `mongodb-memory-server` which downloads and spawns its own `mongod`. After re-prompting with the actual container log, AI identified that `node:20-slim` is missing `libcurl4` and `openssl` which the bundled `mongod` binary dynamically links. **Modified:** added a single `apt-get install --no-install-recommends libcurl4 openssl ca-certificates` step **before** `npm ci`, plus `rm -rf /var/lib/apt/lists/*` to keep the image small (the AI version omitted the cleanup, leaving ~40MB of apt cache in the layer). Verified by running `docker compose run server npm test` — full integration suite now passes inside the container. |

*AI was not used to write any prose section of this report, to generate any figure or diagram, or to edit the video submission. Every code block above was reviewed line-by-line, modified as documented, and exercised by a corresponding unit or integration test before being committed.*
